Method and limits

  • Claims. The README was split into 1191 sentences, bullet items, table cells, and commented command lines, each with its section and the text before it. One Jev question per unit asked whether it states how the code works now. 1072 passed (at 0.5 or more). I picked that question by testing three wordings against 60 units I labeled by hand; it agreed with 53.
  • Code per claim. A program ranked about 18,000 code chunks (functions, tree tables, script windows) by the names each claim gives: paths, module paths, commands and flags, function and type names, tree ids, quoted page text, and numbers. It also used the claim's table row, its context, and the paths its section names, and it followed the calls of the top chunks one step. Jev then judged each of the top ~40 chunks: "is this the code the claim is about?" The best chunks went into the final question, at most about 22k tokens.
  • Judgments. One request per claim, three Jev questions over the same code: about (is this the right code), supported (does it do what the claim says), and contradicted (does it do something different). A program also said where each named file or function is, or that it is missing.
  • Status rules. No code found: about under 0.35. Contradicted: contradicted 0.5 or more and higher than supported. Supported: supported 0.5 or more, and at least 0.15 over contradicted. Else Unclear. I checked these on the data; the margin moved 23 near-ties from Supported to Unclear.
  • My review. I read the code for every claim Jev marked contradicted (45), not only the top 20.
  • Cost. One full pass: 2,327 Jev requests, 25.0M input tokens, $1.05. All runs while I built and tested this: 2,481 requests, 26.7M tokens, $1.12. Price: $0.042 per million input tokens.
  • How far to trust "supported". To test Jev's "supported", I read the code for 20 random supported claims: 16 were right, 2 were wrong, and 2 could not be told from code. So some "supported" claims are wrong too, about 1 in 10 in this small sample. The 2 wrong ones are under Real mismatches. A sample of 20 has a wide error: the true rate can be from about 1 in 100 to 1 in 3.
  • Limits. Jev saw snippets, not whole files, so a claim about what code never does ("it only reads") can read as supported when the shown code agrees and other code differs. Claims about timing, test speed, or live state (cards, clients) cannot be shown by code. The repo was read at one commit; later commits are not in this report.
  • Files. The scripts, logs, and raw results are in ~/Projects/docs-vs-code-check/ (out/results.json holds every claim with its code and Jev's numbers).
